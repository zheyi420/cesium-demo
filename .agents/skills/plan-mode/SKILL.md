# 任务

  

## 步骤  

  

1. 梳理用户的需求描述，读取、分析相关文件。  

2. **必须**用工具 `Ask questions` 或者明确选项提出澄清性问题，获取、梳理与理解用户的回答后，如若需要用户进一步澄清则必须继续提出澄清性问题，直至无需用户再澄清需求为止。  

3. **必须**完成上述第 2 步后，才将你理解的需求描述整理完整后返回给用户，待用户判断你的理解、描述是否正确。若用户对你的总结追加补充，则综合补充内容再次整理理解的需求返回给用户并继续待用户确认。  

4. 用户确认需求后，**才**生成可审阅、可执行的计划；计划需符合最佳实践方案。  

  

## 约定  

  

- 当提出需待用户选择的澄清性问题 (Questions) 时，**必须**在最后追加一个问题：「你还有其他需要补充或特别说明的吗？」  

- **禁止**在用户明确确认需求前输出计划文档。  

  
  

# 需求整理输出格式（仅用户确认前）

  

- **背景与目标**：一两句话说明要解决什么问题。

- **我理解的需求**：分点列出功能、范围、约束、非目标（如有）。
